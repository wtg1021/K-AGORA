# 협의체 자료집 양식 (DB v2)

기준: 첨부된 「2026년 제2회 K-에듀파인 학교회계 시도교육청 업무협의체 협의회」 자료집과 master JSON. 개최일은 2026-10-27이며 상세 안건은 37건입니다.

## 항목

| 구역 | 저장 항목 |
| --- | --- |
| 회의 | 관리번호(`number`), 원문 안건번호(`source_agenda_number`), 협의체/회차, 개최일, 장소, 개최 시도 |
| 제안 | 요구사항명, 기관명, 제안 시도(`region`), 구분(협의체/교육부/SR/간담회/기타), 업무(복수 선택) |
| 요구사항 | 요구사항, 대상 메뉴, 현황, 문제점, 개선방안, 기대효과, 추가 의견 |
| KERIS 사전 검토 | 검토 구분(`review_status`), 상세 본문 표기(`source_status`), 목록 표기(`list_status`), 검토의견 내용(`review`) |
| 사후 처리 | 실제 반영 상태(`status`), 확정 답변(`answer`), 담당 부서, 반영 시점 |
| 출처 | 원문 파일명, PDF 쪽수, URL, 키워드, 검수 메모, 원문 보존 객체(`source_record`) |

업무 표준 항목은 사업 / 예산 / 수입 / 지출 / 계약 / 세무 / 세입세출외현금 / 예산결산 / 발전기금 / 기타입니다. 기존 업무명도 보존합니다. 여러 업무는 `지출 · 계약`처럼 저장하며 API와 화면의 업무 필터는 개별 업무를 포함하는 안건을 모두 찾습니다.

검토 구분은 **미검토 / 현행유지 / 협의필요 / 개선예정**입니다. 실제 반영 상태는 **미확인 / 검토 중 / 일부 반영 / 반영 완료 / 미반영**입니다. 현행유지를 미반영, 개선예정을 반영 완료로 자동 변환하지 않습니다. 자료집 37건의 실제 반영 상태는 전부 미확인으로 시작합니다.

## 첨부 자료 처리

- `documents/2026-school-accounting-02/01-agendas-master-37.json`은 첨부 ZIP과 동일한 전체 master JSON입니다. 가져오기와 초기 등록 시 37건을 새 양식으로 변환합니다. 이전 27건 파일과 달리 현행유지 10건도 포함합니다.
- master의 `document`와 각 원본 `record`를 `source_record`에 보존합니다. 페이지별 추출 텍스트, 원본 필드, 원문 상태, 검수 메모가 함께 백업되며 수정 시 원본은 유지됩니다.
- 요구사항에 덧붙여졌던 `[원문 개선방안]`은 별도 개선방안 항목으로 분리했습니다.
- 목록 기준 구분은 교육부 1건 / 협의체 18건 / 기타 10건 / SR 6건 / 간담회 2건입니다. 알려진 이 자료집의 SHA-256에 한해서 해당 분류를 적용합니다.
- 개최 시도는 충북입니다. 제안 시도는 기관명에서 확인되는 값으로 따로 저장하며 교육부는 전국, 확인되지 않는 경우 미상입니다. 원본의 `region=충북`은 source_record에 보존합니다.
- 상세 본문 기준 검토 구분은 현행유지 10 / 협의필요 23 / 개선예정 4입니다. 13번은 목록의 협의필요와 상세 본문의 개선예정을 모두 보존하고 화면에 차이를 표시합니다.
- 20·21번은 상세 본문 번호를 사용합니다. 나머지 원문 대조 필요 사항은 검수 메모에 보존했습니다.
- PDF 내부 그림·표의 전체 OCR이나 이미지 저장은 추가하지 않았습니다. 페이지별 추출 텍스트를 제공하며 참석자 명단(PDF 127~128쪽)은 데이터에 포함하지 않습니다.

## 기존 DB 이전과 자료 가져오기

시작 시 SQLite `PRAGMA user_version`이 2 미만이면 하나의 트랜잭션으로 기존 JSON 레코드에 새 항목을 추가하고 버전을 2로 올립니다. ID·관리번호·기존 내용·반영 상태를 보존합니다. 기존 행의 미등록 항목은 공란, 검토 구분은 미검토, 구분은 미분류로 시작합니다. 기존 지역 값의 의미는 추측해 변경하지 않습니다.

자료집 37건은 기존 사용자 DB에 자동으로 합치지 않습니다. VS Code의 **K-AGORA: 협의체 실제 자료 37건**은 별도 `data/school-accounting-2026-02.sqlite3`에 최초 1회 등록합니다. 이후 수정·삭제 내용은 재시작 후에도 유지됩니다. 기존 DB 파일 삭제는 필요 없습니다.

기존 DB에 넣으려면 관리자 키를 입력하고 `01-agendas-master-37.json` 또는 v2 앱에서 내보낸 전체 배열 파일을 JSON 가져오기로 선택합니다. master 형식도 직접 처리합니다. 기존 27건을 이미 넣었다면 관리번호가 중복되므로 전체 취소됩니다. 이 경우 별도의 37건 DB 구성을 사용하세요. 사용자 편집 내용이 있을 수 있어 중복 안건을 자동 덮어쓰지 않습니다.

전체 JSON 내보내기에는 원문 보존 객체와 새 항목을 모두 포함합니다. 빈 DB에 복원하면 그대로 유지됩니다. 서버는 UTF-8로 JSON 파일을 읽으므로 Windows CP949 환경에서도 동일하게 동작합니다.
